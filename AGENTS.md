# Omasharp: notes for coding agents

This repo is the `omarchy-app` dotnet template and its bridge (C# ⟷ QML for Omarchy). Read @CONTRIBUTING.md for layout and rules, and @docs/architecture.md before changing `template/bridge/`.

- Full check: `sh scripts/test.sh` (needs the .NET SDK, Qt 6, gcc, clang). Run it before you say you're done.
- To prove a change the way users meet it (a fresh app from this checkout, driven with its `check.sh`), follow `.claude/skills/verify-omasharp/SKILL.md`.
- Apps and examples are written the way the skill in `template/.agents/skills/omasharp/` says (`SKILL.md`, `references/`); it's what agents working on a generated app read, so keep it accurate when you change behavior.
- `analyzers/`: rules fail every app's build, so each must be precise; add the quiet cases to `analyzers/Omasharp.Analyzers.Tests` too.
- Never open windows on the user's screen. Use the skill's `scripts/check.sh` in an app or example (private nested compositor), or Qt's offscreen platform.
- Never add a monitor to the user's Hyprland session, and never send keys or clipboard data to it.
- Bridge changes: keep `template/bridge/host/omasharp.h` and `template/bridge/cs/Native.cs` in sync, and bump `template/bridge/VERSION`.
- Nothing machine-specific in committed files: no home paths, user names, host names or instance ids.
- No code comments. Don't add `//`, `/* */`, `///`, `#`, `--` or `<!-- -->` comments to code you write or change anywhere in this repo (C#, QML, C++, shell, Python, MSBuild, workflows, Lua, qmake, `template/` included), and don't bring back ones that were removed. Say why through names, small functions, tests and commit messages; put explanations users and agents need in the docs (`README.md`s, `docs/`, the skill's `references/`). A script's `--help` text goes in a string or a here-document, never in a header comment the script prints.
  - What stays: directives and metadata that tools read (shebangs, `# shellcheck` directives, `#pragma`, `#if`/`//#if`/`<!--#if` template and preprocessor conditionals, `<auto-generated>` markers, `NOLINT`, `noqa`), text that's data (strings, here-documents, regex literals, test fixtures), files a tool generates, and comments in config dotfiles (`.editorconfig`, `.clang-format`, `.gitignore`, `.gitattributes`).
  - `sh scripts/lint.sh` (CI and the pre-commit hook) fails on any other comment in C#, QML/JS, C++, shell, Python and MSBuild files, and lists each one; remove them by hand. Don't work around the check; if it's wrong about a file, fix `scripts/comments.py`.
